## SchemaSpy vs Azimutt

| | **SchemaSpy** | **Azimutt** |
|---|---|---|
| **Тип** | Статичний HTML-генератор | Інтерактивна SaaS/self-hosted вебапка |
| **Вхідні дані** | Жива БД (JDBC-конект) | SQL dump, DBML, Prisma, JSON schema |
| **Великі схеми** | Ок — одна сторінка на таблицю, немає «одного гігантського графа» | Відмінно — фільтри, «показати тільки суміжні», поступове розкриття |
| **Пошук** | Є (у HTML) | Є + пошук по колонках/типах |
| **ERD** | Є (GraphViz SVG), але layout нефлексибельний | Є + інтерактивне переміщення таблиць |
| **Хостинг** | Генеруєте HTML → кладете у docs-репо, Netlify, GitHub Pages | azimutt.app (безплатний tier) або self-hosted Docker |
| **CI-інтеграція** | Запускається з jar або Docker у CI → артефакт HTML | CLI-імпорт або просто дати URL до SQL у вебапці |
| **Offline** | Так (статичний HTML) | Тільки self-hosted |
| **FK-навігація** | Є (лінки між сторінками) | Краща — граф + клік «розкрити залежності» |
| **Оновлення** | Рідкі; інструмент зрілий, але без активного розвитку | Активний розвиток, команда з продуктовим фокусом |
| **Ліцензія** | LGPL (OSS) | OSS + платний tier |

## Коротко

**SchemaSpy** — якщо хочете статичний HTML прямо в git/docs, без зовнішніх сервісів, і CI-генерацію без зайвих рухів.

**Azimutt** — якщо важлива навігація по великому графу, фільтри «покажи тільки пов'язані з `orders`», та інтерактивне дослідження схеми командою.

Для вашого кейсу (SQL вже є в `npm/er/*.sql`, docs-репо) **Azimutt з SQL-імпортом** або **SchemaSpy в CI через Docker** — обидва органічно лягають поверх того, що вже зроблено. Розгорнути якийсь із них?

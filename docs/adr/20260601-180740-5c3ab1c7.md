З упевненістю можу виділити кілька npm-пакетів:

## Mermaid

| Інструмент | Команда | Що дає |
|---|---|---|
| **`@mermaid-js/mermaid-cli`** | `npx @mermaid-js/mermaid-cli -i er.md -o er.svg` | SVG/PNG/PDF статичний файл; SVG добре зумиться в браузері. Можна підняти ліміти: `-c '{"maxEdges":2000}'` |

Для сотень таблиць: SVG-вихід + `serve` (`npx serve .`) → браузер із zoom. Але layout — одне полотно, навігація обмежена.

## SQL → DBML

| Інструмент | Команда | Що дає |
|---|---|---|
| **`@dbml/cli`** | `npx @dbml/cli sql2dbml --postgres schema.sql -o schema.dbml` | DBML-файл для імпорту в Azimutt, dbdocs, dbdiagram.io |
| **`dbdocs`** | `npx dbdocs build schema.dbml` | Публікує інтерактивну схему на dbdocs.io (безкоштовний tier; потрібен акаунт; схема йде в хмару) |

## Практична схема для вашого pipeline

```yaml
# Після sync-schema (npm/er/maya.sql вже є)
- name: Export ER diagram
run: |
# sql → dbml
npx @dbml/cli sql2dbml --postgres docs/npm/er/maya.sql -o docs/npm/er/maya.dbml
# mermaid → svg (якщо хочете статичний artifacts)
npx @mermaid-js/mermaid-cli -i docs/npm/er/maya.md -o docs/npm/er/maya.svg
```

Або просто `maya.dbml` → відкрити в Azimutt (`Import`) / `dbdocs build` → посилання в команду.

**Чесно про обмеження:** `mmdc` на сотнях таблиць все одно дасть щільний граф — зумиться, але читабельність залежить від layout. Для **«знайди зв'язки між X і Y»** — Azimutt із DBML-імпортом значно краще. Хочете, щоб я додав у `sync-schema` автоматичну генерацію `.dbml` поряд із `.sql` і `.md`?

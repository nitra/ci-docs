## ADR npm пакет @nitra/ci-shared — публічний доступ через publishConfig

**Контекст:** Скоуповані npm-пакети (`@scope/name`) за замовчуванням публікуються як private, що призводило б до помилки `402 Payment Required` при публікації без `publishConfig.access: "public"`.

**Рішення/Процедура/Факт:** У `npm/package.json` додано поле `"publishConfig": { "access": "public" }`. Workflow `npm-publish.yml` використовує `JS-DevTools/npm-publish` з action-level `access: public` — обидва варіанти разом гарантують публічність пакета незалежно від клієнта.

**Обґрунтування:** `@nitra/ci-shared` — open-source інструментарій CI, має бути доступний без авторизованого npm-аккаунту організації. `publishConfig` у `package.json` — рекомендований npm-спосіб задекларувати access-рівень разом з пакетом.

**Розглянуті альтернативи:** Передавати `--access public` у командному рядку `npm publish` — не обрано, оскільки це легко забути в CI; `publishConfig` у `package.json` є самодокументованим і не залежить від CLI-аргументів.

**Зачіпає:** `npm/package.json` (нове поле `publishConfig`), `.github/workflows/npm-publish.yml`.

## Knowledge npm E404 при першому публіші скоупованого пакета — вимоги org

**Контекст:** Спроба `npm publish` завершилась `404 Not Found - PUT https://registry.npmjs.org/@nitra%2fci-shared` — пакет не знайдений і немає прав на його створення. `publishConfig.access: "public"` не допомагає, бо помилка виникає ще до перевірки прав доступу.

**Рішення/Процедура/Факт:** Для публікації в скоуп `@nitra` необхідно:

1. Переконатись, що org `@nitra` існує на npmjs.com (`npm org ls nitra`).
2. Бути членом org з роллю `developer` або вище.
3. Бути залогіненим у правильний npm-аккаунт (`npm whoami`).
4. Якщо org вимагає 2FA з режимом `auth-and-writes` — передавати `--otp=<код>`.
   npm автоматично не створює скоуп при першій публікації — org має існувати наперед.

**Обґрунтування:** npm скоупи прив'язані до org-аккаунту на npmjs.com. `E404` при `PUT` — стандартна відповідь реєстру, якщо scoped-пакет ніколи не існував і/або у сесії немає прав на цей скоуп, незалежно від `access: public`.

**Розглянуті альтернативи:** Не обговорювалися.

**Зачіпає:** процес первинного npm-публішу; `~/.npmrc` (токен авторизації); налаштування org на npmjs.com.

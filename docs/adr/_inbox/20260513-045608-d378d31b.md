## ADR Додавання `publishConfig.access: "public"` для скоупованого пакета

**Контекст:** npm за замовчуванням публікує скоуповані пакети (`@nitra/ci-shared`) як private; без явного `access: "public"` перший `npm publish` завершується з `E404` або `E402`.

**Рішення/Процедура/Факт:** Додано у `npm/package.json` поле `"publishConfig": { "access": "public" }`. Це єдина зміна, потрібна на рівні пакета; CI-action `JS-DevTools/npm-publish` підхоплює значення автоматично.

**Обґрунтування:** Альтернатива — передавати прапор `--access public` у CLI або в `with: access: public` у workflow — є менш надійною, бо залежить від конкретного action і може бути пропущена при зміні CI. Поле у `package.json` є єдиним джерелом правди і діє і локально, і в CI.

**Розглянуті альтернативи:** `npm publish --access public` у workflow (відкинуто — хрихке); `access: public` у `JS-DevTools/npm-publish` (прийнятне, але дублює логіку).

**Зачіпає:** `npm/package.json` (поле `publishConfig`)

## ADR Виправлення lint-порушень у тестових файлах та `cli.mjs` (n-lint)

**Контекст:** Після приведення до канону `bun run lint` виявив порушення oxlint/ESLint у тестах і в CLI: `process.exit()`, відсутні JSDoc-типи, невикористаний імпорт, regexp literals у test-scope, `map(fn)` замість `map(x => fn(x))`.

**Рішення/Процедура/Факт:**

- `npm/src/cli.mjs`: замінено `process.exit(1)` на `process.exitCode = 1` + `else`-гілка (правило `n/no-process-exit`)
- `npm/src/sync-schema/main.mjs`: `values.header.map(parseHeader)` → `values.header.map(h => parseHeader(h))` (правило `unicorn/no-array-callback-reference`)
- `npm/test/sync-schema/main.test.mjs`: додано `@param {type}` + `@description` до `setupTmpDocs`, `setupBareDocs`, `startMockGraphql`; виведено `INVALID_HEADER_REGEX` у module scope; замінено hardcoded `/tmp/nowhere` на `join(tmpdir(), '...')`
- `npm/test/commit-push/main.test.mjs`: прибрано невикористаний `readFileSync`; виведено `SHA_REGEX = /^[0-9a-f]{40}$/` у module scope; замінено `/tmp/x` на `tmpdir()`
- `.cspell.json`: додано 22 слова (українські запозичення та IT-терміни) для знятку false-positive cspell-помилок у ADR-файлах

**Обґрунтування:** `process.exit()` порушує `n/no-process-exit` — Node.js-канон вимагає кидати Error або виставляти `process.exitCode`; inline регулярні вирази у тестах порушують sonarjs-правила про повторне використання; `/tmp/x` як hardcoded шлях може не існувати на CI-агентах (publicly-writable).

**Розглянуті альтернативи:** Додати `eslint-disable` коментарі — відкинуто (маскує проблему замість виправлення).

**Зачіпає:** `npm/src/cli.mjs`, `npm/src/sync-schema/main.mjs`, `npm/test/sync-schema/main.test.mjs`, `npm/test/commit-push/main.test.mjs`, `.cspell.json`

## Knowledge Knip false-positives у проєктах, що слідують канону `@nitra/cursor`

**Контекст:** Запуск `bunx knip` у `@nitra/ci-shared` (100% pass `npx @nitra/cursor check`) дає 9 попереджень, хоча реального мертвого коду немає — це структурний конфлікт між підходами knip і канону `@nitra/cursor`.

**Рішення/Процедура/Факт:** Усі 9 — false positives трьох типів:

1. **Unused files** (`eslint.config.js`, `stylelint.config.cjs`, `**/*.test.mjs`): knip не бачить CLI-конфіги (підвантажує CLI, а не JS-import) і test-файли (запускаються `bun test` через glob, без прямих imports)

**Обґрунтування:** Патч `knip.json` на рівні споживача — тимчасовий workaround; системне рішення — канонічний `knip.json` у `@nitra/cursor`, щоб усі репозиторії-споживачі отримали його автоматично (за аналогією з `oxlint-canonical.json`).

**Зачіпає:** Усі репозиторії-споживачі `@nitra/cursor` (правила `n-js-lint`, `n-bun`, `n-text`); задача на доопрацювання — репозиторій `@nitra/cursor`

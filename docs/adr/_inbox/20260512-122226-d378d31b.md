Додано `"publishConfig": { "access": "public" }` у `npm/package.json`. Цього достатньо — коли `npm-publish.yml` запускає `npm publish`, npm бачить цей прапорець і публікує пакет як публічний незважаючи на `@nitra/` скоуп.

## ADR Конфігурація `publishConfig.access: "public"` для скоупованого npm-пакета

**Контекст:** Пакет `@nitra/ci-shared` є скоупованим (`@nitra/`). За замовчуванням npm публікує скоуповані пакети як приватні, що вимагає платного плану або окремого npm-організаційного доступу.

**Рішення/Процедура/Факт:** До `npm/package.json` додано поле `"publishConfig": { "access": "public" }`. Workflow `npm-publish.yml` використовує OIDC і `npm publish` — цього поля достатньо без додаткових прапорців CLI.

**Обґрунтування:** Пакет призначений для відкритого використання в CI-пайплайнах; публічний доступ — явна вимога. `publishConfig` зберігає налаштування разом з пакетом, а не розпорошує їх між workflow і CLI-аргументами.

**Розглянуті альтернативи:** `npm publish --access public` у workflow-кроці — еквівалентно, але менш явно; налаштування приватності через UI npmjs.com — не автоматизовано.

**Зачіпає:** `npm/package.json` (`publishConfig`), `.github/workflows/npm-publish.yml` (публікація через OIDC).
